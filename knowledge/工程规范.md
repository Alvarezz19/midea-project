# 工程规范

本文档用于约束工程 JSON 生成和改造，避免智能体破坏模板结构、命名规范和关键保护逻辑。

## 修改原则

默认采用“模板优先、局部改造”的原则。系统应先选择最接近需求的完整工程模板，再基于用户需求做局部修改。

LLM 不应直接输出完整 JSON。LLM 应输出结构化补丁意图，由程序执行读取、定位、修改、校验和保存。

## 上下文加载

完整工程 JSON 不应在每轮对话中全部放入上下文。应先加载模板摘要、tab 摘要、节点摘要，再按需加载相关节点邻域。

涉及具体修改时，应加载目标节点、上下游邻域、所在 tab 摘要和相关 schema。

## 节点选择

补丁操作必须使用唯一节点选择器。若选择器匹配多个节点，系统必须停止并要求用户或上游规划节点进一步限定范围。

推荐优先使用节点 id。若没有 id，可组合使用 tab、type、name、关键参数和邻域信息。

## 结构字段保护

普通参数修改不得直接修改 `id`、`type`、`z`、`wires` 等结构字段。

如果确实需要改连线，应使用专门的 `connect`、`disconnect` 或局部子图操作，并在执行后做拓扑校验。

## 版本管理

任何修改都不应覆盖原始模板。系统应为用户工程创建独立版本，并记录来源模板、版本 id、修改摘要和校验结果。

导出前必须确认当前版本校验通过。

## 校验要求

每次修改后必须至少校验 JSON 根结构、节点 id、节点 type、重复 id、tab 引用、subflow 引用、wires 上游源引用和输入端口数量。

校验失败时不应导出，应回到补丁规划或人工确认步骤。

## 高风险操作

删除节点、删除连线、改变设备数量、改变 IO 点位、绕过保护逻辑、修改通讯地址、修改故障联锁，都属于高风险操作。

高风险操作必须要求人工确认，并在摘要中列出影响范围。

## 不可默认删除的逻辑

防冻保护、故障报警、运行反馈、手自动状态、设备可用状态、最小启停延时、运行时间累计、通讯输出和关键联锁不应默认删除。

用户要求简化程序时，也应优先隐藏、旁路或参数化，而不是直接删除这些逻辑。

## 命名规范

节点名称应表达设备、信号和功能，例如“冷冻泵运行反馈”“送风温度设定”“旁通阀压差 PID”。

新增备注应说明修改依据和日期语义，但不应写入无关对话内容。

## 导出检查

导出前应检查当前版本路径、模板来源、修改摘要、校验结果、未解决问题和高风险操作确认记录。

导出的 JSON 应保持 UTF-8 编码，并保留模板原有字段风格。
