# 补丁配方

本文档用于支持创建工程版本后的局部改造规划。内容面向结构化补丁，不替代工程控制策略；当业务策略和补丁配方冲突时，以控制策略和工程规范为准。

## AHU CO2 浓度设定接入新风阀控制

适用：AHU、空调箱、新风阀联动、CO2 控制。

用户常见说法：

- 新增 CO2 设定接到新风阀控制。
- CO2 浓度高了要加大新风阀。
- 把 CO2 设定接入比较判断。

推荐定位：

- tab：控制、新风阀控制、CO2 控制。
- node_type：compare、pid、constInput、swInput、hwInput。
- query：CO2 新风阀 比较判断 动态阈值 设定。

推荐操作组合：

1. `add_node_from_schema` 新增 `constInput` 或 `swInput` 作为 CO2 设定。
2. 若接入比较判断阈值，先 `enable_dynamic_input(compare)`。
3. `connect(设定节点 -> compare target_input=1)`。

风险：

- 至少 medium，因为会新增节点并修改输入连线。
- 若接入新风阀执行输出、风机联锁或保护链路，升为 high。
- 不应绕过送风机运行条件；风机未运行时不应单独打开新风阀。

## AHU 送风温度 PID 动态设定

适用：AHU 送风温度、回风温度、水阀、直膨机、电加热 PID 控制。

用户常见说法：

- 送风温度设定改成动态输入。
- 新增送风温度设定接到 PID。
- PID 输出上限或下限改成可调设定。

推荐定位：

- tab：控制、温度控制、直膨机控制。
- node_type：pid、constInput、swInput。
- query：送风温度 PID dynamic input highPidOutLimit lowPidOutLimit setpoint。

推荐操作组合：

1. `add_node_from_schema` 新增 `constInput` 或 `swInput`。
2. `enable_dynamic_input(pid)`，必须指定 `input_option`，例如 `highPidOutLimit`、`lowPidOutLimit`、`proportional`、`integral`、`deadBand`。
3. `connect(设定节点 -> PID 新增动态输入端)`。

风险：

- 至少 medium。
- 修改 PID 输出上限、下限、比例、积分、死区会影响控制品质，确认摘要必须说明被启用的 `input_option`。

## AHU 过滤网报警

适用：过滤网压差开关、压差传感器、报警输出、通讯发布。

用户常见说法：

- 新增过滤网报警。
- 过滤网压差报警接入系统。
- 过滤网堵塞要报警。

推荐定位：

- tab：控制、报警、IO、通讯。
- node_type：hwInput、swInput、compare、modbusOutput、bacipOutput。
- query：过滤网 压差 报警 物理输入 通讯输出。

推荐操作组合：

1. 优先定位已有硬接 DI、软件输入或通讯输入。
2. 若只缺报警判断，可新增 `compare` 或直接复用布尔输入。
3. 若涉及输出点表，用 `set_io_point` 修改已有点位，不凭空新增现场地址。

风险：

- 新增报警判断通常 medium。
- 修改 IO/通讯点位为 high。
- 过滤网报警不应替代防冻、风机故障等安全保护。

## AHU 防冻保护保留和禁止旁路

适用：防冻开关、防冻报警、新风阀、热水阀、送风机联锁。

用户常见说法：

- 暂时不要防冻保护。
- 防冻报警先断开。
- 防冻时只报警不联锁。

推荐定位：

- tab：控制、保护、报警、IO。
- node_type：hwInput、compare、logic、trigger、hwOutput。
- query：防冻 保护 联锁 新风阀 热水阀 风机。

推荐操作组合：

1. 不自动删除或断开防冻保护链路。
2. 若用户要求调整阈值，可只规划 `replace_constant` 或 `update_param`。
3. 若用户明确要求断开保护，返回 high 风险计划或追问人工确认，不自动应用。

风险：

- 删除、断开、禁用防冻保护必须 high。
- 必须提示可能导致低温冻裂、阀门和风机联锁失效。

## 机房水泵运行台数阈值修改

适用：机房群控、水泵控制、运行台数、比较判断。

用户常见说法：

- 水泵运行台数阈值改为 3。
- 水泵控制里的比较判断改成 2 台。
- 把刚才那个水泵比较判断阈值改一下。

推荐定位：

- tab：水泵控制、联动控制。
- node_type：compare、constInput、swInput。
- query：水泵 控制 运行台数 比较判断 阈值 tripPoint。

推荐操作组合：

1. 唯一定位 compare 时，优先 `update_param({"tripPoint": 新值})`。
2. 若目标是常量或软件输入设定，用 `replace_constant` 修改 `fixedValue` 或 `outOfServiceValue`。
3. 若存在多个比较判断，必须展示候选，不要求用户提供节点 ID。

风险：

- 单个阈值修改通常 low。
- 如果改变运行台数、备用策略或故障切换逻辑，升为 high。

## 机房旁通阀压差设定修改

适用：旁通阀控制、压差控制、PID、比较判断、限值。

用户常见说法：

- 旁通阀压差设定改为 45。
- 把旁通阀比较判断阈值调高。
- 旁通压差设定值改一下。

推荐定位：

- tab：旁通阀控制、水泵控制。
- node_type：compare、pid、limit、constInput、swInput。
- query：旁通阀 压差 设定 比较判断 PID 限值。

推荐操作组合：

1. 若目标是静态 compare 阈值，使用 `update_param({"tripPoint": 新值})`。
2. 若目标是常量或软件输入，使用 `replace_constant`。
3. 若目标不唯一，展示压差、上游、下游和当前设定值候选。

风险：

- 单个设定修改通常 low。
- 若影响旁通阀开度输出、PID 限幅或保护联锁，升为 medium 或 high。

## 机房旁通阀压差设定新增并接入比较判断

适用：旁通阀控制页，新增可调压差设定并接入已有比较判断。

用户常见说法：

- 新增旁通阀压差设定。
- 把压差设定接入旁通阀比较判断。
- 旁通阀压差改成动态设定。

推荐定位：

- tab：旁通阀控制。
- node_type：compare、pid、constInput、swInput。
- query：旁通阀 压差 比较判断 设定 动态阈值。

推荐操作组合：

1. `add_node_from_schema(constInput 或 swInput)`。
2. `enable_dynamic_input(compare)`。
3. `connect(设定节点 -> compare target_input=1)`。

风险：

- 至少 medium。
- 如果影响保护、联锁、旁通阀执行输出或 IO 点位，升为 high。

## PID 输出上限和下限动态输入

适用：PID 控制器输出限幅、风阀、水阀、变频器。

用户常见说法：

- PID 输出上限改成动态输入。
- 输出下限接一个设定值。
- 给 PID 加一个可调上限。

推荐定位：

- node_type：pid、constInput、swInput。
- query：PID highPidOutLimit lowPidOutLimit 动态输入 输出上限 输出下限。

推荐操作组合：

1. 新增或定位设定节点。
2. `enable_dynamic_input(pid, input_option="highPidOutLimit")` 或 `input_option="lowPidOutLimit"`。
3. `connect(设定节点 -> PID 对应动态输入端)`。

风险：

- 至少 medium。
- 输出上限、下限会限制执行器开度或频率，确认摘要必须说明新范围来源。

## 比较判断动态阈值输入

适用：compare、limit、阈值、门限、动态设定。

用户常见说法：

- 比较判断阈值改成动态。
- 新增设定接到比较判断第 2 个输入。
- 让比较值来自软件输入。

推荐定位：

- node_type：compare、limit、constInput、swInput。
- query：比较判断 阈值 动态输入 tripPoint target_input=1。

推荐操作组合：

1. 若已有设定节点，直接定位设定节点和 compare 节点。
2. 若没有设定节点，先 `add_node_from_schema`。
3. `enable_dynamic_input(compare)`。
4. `connect(设定节点 -> compare target_input=1)`。

风险：

- 至少 medium。
- 不要用 `connect` 隐式创建输入端，必须先启用动态输入。

## IO 和通讯点位修改风险

适用：硬接 IO、Modbus、BACnet/IP、MQTT、对象号、地址、通道。

用户常见说法：

- 把这个点位通道改为 31。
- Modbus 地址改一下。
- BACnet 对象号改成 1001。

推荐定位：

- node_type：hwInput、hwOutput、modbusInput、modbusOutput、bacipInput、bacipOutput、mqttInput、mqttOutput。
- query：点位 通道 地址 Modbus BACnet 对象号 hwChannelIndex。

推荐操作组合：

1. 只对已唯一定位的 IO/通讯节点使用 `set_io_point`。
2. 参数只允许白名单字段，例如 `hwExpander`、`hwChannelIndex`、`modbusAddress`、`modbusRegAddr`、`bacnetObjectInstance`、`topic`、`objectName`。
3. 若字段或值不明确，追问点位对象和值，不要求用户提供内部字段名。

风险：

- 始终 high。
- 必须提示检查通道、地址、对象号冲突和现场点表一致性。

## copy_block 边界接线确认

适用：复制功能块、克隆逻辑、复用旁通阀或水泵控制段。

用户常见说法：

- 复制旁通阀控制功能块。
- 把这个控制段复制到另一个页面。
- 复制后接到原来的输入输出。

推荐定位：

- block：功能块索引中的 `block_id`。
- tab：目标页面。
- query：copy_block 功能块 边界接线 入口 出口。

推荐操作组合：

1. 默认只 `copy_block` 内部节点和内部连线。
2. 默认丢弃外部入口和出口，不自动接外部线。
3. 只有用户基于边界预览明确给出入口、出口、方向和端口时，才允许 `boundary_connections`。

风险：

- 始终 high。
- 必须提示复制节点会重写 id，并禁用复制节点的本地 BACnet 暴露对象，避免对象号复用。

## 删除或断开保护链路的禁止和确认策略

适用：防冻、故障、急停、联锁、水流、反馈、保护输出。

用户常见说法：

- 断开保护线。
- 删除这个故障判断。
- 保护先不要。

推荐定位：

- query：保护 联锁 故障 急停 防冻 水流 反馈 断开 删除。
- node_type：hwInput、compare、logic、trigger、hwOutput、modbusOutput。

推荐操作组合：

1. 不自动删除保护节点。
2. 若只是修改保护阈值，可使用 `replace_constant` 或 `update_param`。
3. 若用户明确要求断开，必须 high 风险并进入人工确认。
4. 如果无法确认替代保护路径，返回追问，不生成可应用补丁。

风险：

- 始终 high。
- 必须说明可能切断设备保护、故障反馈或安全联锁。
