## 1. 当前进度总览

项目已从原型状态推进到“可持续迭代的本地工程底座”阶段。

已完成：

- 阶段 0 基础工程整理：依赖文件、环境变量示例、配置模块、日志模块、LangGraph 单例编译、`wires` 方向术语统一。
- 阶段 1 本地可验收底座：PostgreSQL 初始业务 schema、文件型 session store、LangGraph 内存 checkpointer、可配置 PostgreSQL checkpointer 边界、Docker PostgreSQL 集成验收、PostgreSQL session/version/patch/validation/audit 运行时存储、不可变子版本、版本列表、回滚接口。
- 补丁执行底座增强：dry-run、节点级 diff 摘要、dry-run API、工作流应用补丁前复用 dry-run。
- 版本对比增强：支持按项目版本 ID 生成节点级 diff 摘要，提供 `/api/projects/{project_id}/diff`。
- 导出安全增强：校验报告包含导出阻塞原因，导出接口拒绝 error 级无效工程。
- 阶段 3 局部上下文底座：新增功能块索引 `block_index.jsonl` 和 `/api/blocks/search`。
- 阶段 3 剩余核心项：新增按 `block_id` 加载预算受控局部 JSON 上下文和 `/api/blocks/context`。
- 阶段 3 节点索引增强：`node_index.jsonl` 已显式关联模块 schema，包含 schema 路径、分类、名称、module_type 和参数字段列表。
- 阶段 4 LLM 底座：新增 LLM Gateway，默认 DeepSeek，预留 OpenAI/Azure OpenAI/Anthropic 配置入口，支持结构化需求抽取。
- 阶段 4 结构化 planner dry-run：新增 LLM 补丁规划服务，显式开启后可输出受 schema 约束的多步补丁，并立即由 patch engine dry-run 和校验。
- 阶段 4 planner 评测底座：新增 `evals/patch_planning_cases.jsonl` 和 pytest 评测入口，覆盖 golden plan schema、dry-run 和真实 DeepSeek 结构化规划。
- 阶段 4 planner 失败反馈重试：schema 校验失败、dry-run 执行失败或校验失败时，可反馈错误给 LLM 重新规划。
- 阶段 4 工作流接入：LangGraph 自然语言补丁规划节点可显式启用 LLM planner，并复用 API dry-run 的重试、校验和错误反馈机制；low 风险计划可自动应用，中高风险计划停在确认状态。
- 阶段 4/5 衔接：补齐状态/API/静态工作台层的补丁确认闭环，中高风险计划和手动中高风险补丁确认前只 dry-run，不创建新版本；确认后应用并生成子版本，取消后清理待确认补丁。
- 阶段 2/4 interrupt：模板确认和中高风险补丁确认已迁移到 LangGraph 原生 `interrupt()` / `Command(resume=...)`，API 入口保持兼容，确认前状态不落盘变更，确认后从 checkpoint 恢复执行。
- 阶段 2A：工作流接入确定性结构化需求摘要，模板选择前可生成待澄清问题；模板候选补充匹配项、缺失项、预计改造成本和风险点；新增模板选择评测样例。
