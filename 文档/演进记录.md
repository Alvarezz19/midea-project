## 1. 当前进度总览

项目已从原型状态推进到“可持续迭代的本地工程底座”阶段。

已完成：

- 阶段 0 基础工程整理：依赖文件、环境变量示例、配置模块、日志模块、LangGraph 单例编译、`wires` 方向术语统一。
- 阶段 1 本地可验收底座：PostgreSQL 初始业务 schema、文件型 session store、LangGraph 内存 checkpointer、可配置 PostgreSQL checkpointer 边界、Docker PostgreSQL 集成验收、PostgreSQL session/version/patch/validation/audit 运行时存储、不可变子版本、版本列表、回滚接口。
- 补丁执行底座增强：dry-run、节点级 diff 摘要、dry-run API、工作流应用补丁前复用 dry-run。
- 版本对比增强：支持按项目版本 ID 生成节点级 diff 摘要，提供 `/api/projects/{project_id}/diff`。
- 导出安全增强：校验报告包含导出阻塞原因，导出接口拒绝 error 级无效工程。
- 阶段 3 局部上下文底座：新增功能块索引 `block_index.jsonl` 和 `/api/blocks/search`。
- 阶段 3 剩余核心项：新增按 `block_id` 加载预算受控局部 JSON 上下文和 `/api/blocks/context`。
- 阶段 3 节点索引增强：`node_index.jsonl` 已显式关联模块 schema，包含 schema 路径、分类、名称、module_type 和参数字段列表。
- 阶段 4 LLM 底座：新增 LLM Gateway，默认 DeepSeek，预留 OpenAI/Azure OpenAI/Anthropic 配置入口，支持结构化需求抽取。
- 阶段 4 结构化 planner dry-run：新增 LLM 补丁规划服务，显式开启后可输出受 schema 约束的多步补丁，并立即由 patch engine dry-run 和校验。
- 阶段 4 planner 评测底座：新增 `evals/patch_planning_cases.jsonl` 和 pytest 评测入口，覆盖 golden plan schema、dry-run 和真实 DeepSeek 结构化规划。
- 阶段 4 planner 失败反馈重试：schema 校验失败、dry-run 执行失败或校验失败时，可反馈错误给 LLM 重新规划。
- 阶段 4 工作流接入：LangGraph 自然语言补丁规划节点可显式启用 LLM planner，并复用 API dry-run 的重试、校验和错误反馈机制；low 风险计划可自动应用，中高风险计划停在确认状态。
- 阶段 4/5 衔接：补齐状态/API/静态工作台层的补丁确认闭环，中高风险计划和手动中高风险补丁确认前只 dry-run，不创建新版本；确认后应用并生成子版本，取消后清理待确认补丁。
- 阶段 2/4 interrupt：模板确认和中高风险补丁确认已迁移到 LangGraph 原生 `interrupt()` / `Command(resume=...)`，API 入口保持兼容，确认前状态不落盘变更，确认后从 checkpoint 恢复执行。
- 阶段 2A：工作流接入确定性结构化需求摘要，模板选择前可生成待澄清问题；模板候选补充匹配项、缺失项、预计改造成本和风险点；新增模板选择评测样例。
- 阶段 2B：模板选择评测扩充到 AHU 和机房群控各 10 个可推荐样例，并在测试中统计 Top-1/Top-3 命中率。
- 阶段 5A：新增 `replace_constant` 低风险补丁操作，支持常量、软件输入设定值、比较阈值和数学模块固定值的受限替换，并接入规则 planner、LLM planner schema、dry-run、diff、风险分级和评测。
- 阶段 5B：新增 `enable_dynamic_input` 中风险补丁操作，支持 `compare/limit` 的 `inputAuxEnable` 动态端口和 `pid/fuzzypid/linear` 的动态输入选项，确认前只 dry-run。
- 阶段 6 前置：新增动态端口一致性校验，覆盖 `inputAuxEnable`、`inputsOption`、`inputD/outputD`、`inputsCount`、`inputs` 和 `wires` 的一致性。
- 阶段 5C：扩充组合补丁评测样例，覆盖 `add_node_from_schema + enable_dynamic_input + connect` 的 AHU CO2、AHU PID 参数动态化和机房群控旁通阀压差设定链路。
- 阶段 5D：新增 `copy_block` 高风险补丁操作第一版，支持按 `block_id` 复制内部节点和内部连线、重写 id、坐标偏移、目标 tab 选择，并丢弃外部入口/出口连线。
- 阶段 5F：补齐 `copy_block` 边界预览和显式接线辅助，dry-run 返回入口/出口端口、复制后节点映射和 `boundary_connections` 草案；只有用户显式提供 entry/exit 映射时才接外部线。
- 阶段 6A：新增 schema 参数合法性校验，覆盖 schema 已知节点的字段类型、枚举、范围、必填参数和未知字段。
- 阶段 6B：新增 IO/通讯冲突校验，覆盖硬件 IO 通道、Modbus 点位、本地 BACnet 对象、BACnet/IP 远端点位和 MQTT `objectName` 重复；同步让 `copy_block` 禁用复制节点上的本地 BACnet 暴露对象，避免复制后复用原对象号。
- 阶段 5E：新增 `set_io_point` 高风险补丁操作，支持修改已有硬件 IO、Modbus、本地 BACnet、BACnet/IP 和 MQTT 点位白名单字段，并复用 dry-run 校验阻断点位冲突。
- 阶段 6C：新增保护逻辑规则库第一版，覆盖关键执行器输出缺少上游联锁、保护/故障/反馈/报警信号被停用，以及 AHU/机房群控关键设备缺少故障、运行或反馈线索。
- 阶段 6D：保护逻辑规则迁移到机器可读 `rules/protection_logic.json`，校验器从规则文件加载保护关键词、关键执行器和设备保护线索规则，并保留默认兜底规则。
- 阶段 6E：保护规则补充链路影响范围第一版，覆盖关键执行器常量直连旁路、防冻信号存在但未进入送风机/新风阀上游链路，以及规则级业务例外白名单。
- 阶段 6F：保护规则补充读写方向第一版，覆盖物理输入/订阅输入不应被上游节点驱动，以及物理输出不应命名为故障、反馈、状态、报警、防冻、急停或到位等读信号。
- 阶段 6G：校验报告格式升级，补充 `summary` 和问题级 `suggestion`，保持原有 `error_count`、`warning_count` 兼容字段。
- 阶段 6H：补丁 dry-run 接入 L6 变更风险校验，覆盖保护节点删除、关键执行器删除、保护关键词移除和保护链路断线。
- 阶段 6I：保护规则扩充设备级规则，新增电加热故障、过滤网报警和旁通阀限幅/上下限线索校验。
- 阶段 7.1：冻结前后端契约和事件模型，新增 SSE 事件回放、trace 查询、项目 trace 列表、反馈、metrics、工程版本局部 React Flow 摘要接口，以及 file/PostgreSQL 可观测性存储边界。
- 阶段 7.2：新增 `frontend/` Vite + React + TypeScript 工作台脚手架，接入 Ant Design、TanStack Query、Zustand、React Router、React Flow、Zod、Vitest；FastAPI 根路径默认托管 React 构建产物，旧静态原型保留在 `/legacy`。
