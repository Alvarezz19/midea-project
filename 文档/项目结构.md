# 项目结构

更新时间：2026-04-29

用途：给 Codex 快速了解仓库结构和维护边界。本文只记录长期稳定的结构信息；详细运行方式、能力说明和路线规划分别看 `README.md`、`文档/生产级智能体系统改进方案.md`、`文档/阶段7生产前端与可观测性实施方案.md` 和 `文档/阶段7前后端契约.md`。

## 维护原则

- 只记录目录/模块职责、关键入口、运行时产物边界。
- 不展开 API 细节、测试断言、完整功能说明，避免文档膨胀。
- 结构变更后同步更新本文；普通业务逻辑小改不必更新。

```text

  -> requirement_analysis.py 确定性需求摘要与澄清问题
  -> requirement_extractor.py LLM 结构化抽取需求（显式 API 调用）
  -> app/services/retrieval.py / knowledge.py
  -> json_project.py 创建版本
  -> planner.py / llm_planner.py 规划补丁意图
  -> patch_engine.py 执行补丁
  -> validator.py 校验
  -> 导出 JSON
```

## 运行时产物

```text
projects/
  sessions/                 文件型会话状态输出目录
  events/                   文件型 SSE/workflow 事件 JSONL
  traces/                   文件型 trace 详情 JSON
  feedback/                 文件型用户反馈 JSONL
  versions/
    {project_id}/
      {version_id}.json
      {version_id}.meta.json 版本来源、父版本、hash、补丁摘要和校验摘要
```

`projects/versions/` 是默认版本输出目录。`RUNTIME_STORE_BACKEND=file` 时，会话状态写入 `projects/sessions/`，事件、trace 和反馈分别写入 `projects/events/`、`projects/traces/`、`projects/feedback/`；切换到 PostgreSQL 后，session、版本元数据和阶段7可观测性数据写入数据库，工程 JSON 文件本体仍保存在版本目录。测试应优先使用临时目录，避免污染真实运行时版本。

## 当前结构性限制

- 会话和版本运行时默认仍使用文件型存储；设置 `RUNTIME_STORE_BACKEND=postgres` 且配置 `DATABASE_URL` 后，session、project/version 元数据、patch、validation、export 和 audit 会写入 PostgreSQL，工程 JSON 文件本体仍保存在 `projects/versions/` 或配置目录。
- PostgreSQL 运行时存储和 LangGraph PostgreSQL checkpointer 已完成 Docker 本地集成验收；当前仍缺权限模型、运维查询和更细粒度审计检索等生产化配套。
- 补丁应用成功后会创建新的子版本并更新当前版本指针，不覆盖父版本 JSON。
- 回滚会把当前版本指针切回已有版本，版本目录中的历史文件不会删除。
- 补丁引擎支持 dry-run、节点级 diff 摘要、`rename_node`、`replace_constant` 低风险常量/设定值替换、`add_node_from_schema`、`connect`、`disconnect`、`enable_dynamic_input` 中风险动态输入端口启用、`copy_block` 高风险功能块复制和 `set_io_point` 高风险 IO/通讯点位修改；API 返回摘要，不返回完整工程节点数组。
- 项目版本支持按版本 ID 生成节点级 diff 摘要；前端已提供摘要级版本历史、任意版本对比、父子 diff 快捷查看和回滚确认，不拉取完整工程 JSON。
- 阶段7前后端契约已新增 SSE 事件回放、trace 查询、trace/project 反馈查询、metrics、成本聚合、趋势聚合和工程版本局部 React Flow 摘要接口；前端已消费 SSE 事件流并展示连接状态、步骤条、事件抽屉、Trace 详情、指标图表、LLM 成本和观测趋势。当前 API 主工作流、独立 planner API、校验、导出、LLM 调用、补丁提交、版本创建和工程校验都已写入 trace/events。
- 导出接口会重新校验目标工程；存在 error 级阻塞问题时拒绝导出。
- 索引层级已包含功能块级 `blocks/block_index.jsonl`，支持局部功能块检索、按 `block_id` 加载预算受控的局部 JSON 上下文和入口/出口边界端口预览；`copy_block` 支持内部节点/内部连线复制、边界预览、显式 `boundary_connections` 接线辅助，并会禁用复制节点上的本地 BACnet 暴露对象，避免复用原对象号。
- 节点索引 `nodes/node_index.jsonl` 已按节点 `type` 显式关联 `schemas/*/*.json` 的 `module_type`，每行包含 `schema_matched`、`schema_path`、`schema_category`、`schema_name`、`schema_module_type` 和 `schema_parameter_fields`；未匹配 schema 的节点会保留空关联字段。
- 工作流已接入确定性需求摘要和模板候选解释；当前会在项目类型或基本设备/控制目标不足时先进入澄清状态，通讯、保护逻辑和设备数量缺口会作为待确认问题展示。
- LLM Gateway 已接入 DeepSeek JSON 输出并预留 OpenAI、Azure OpenAI、Anthropic 配置入口；当前用于结构化需求抽取和显式开启的 LLM 结构化 planner dry-run，planner 支持 schema/dry-run 失败反馈重试，并已接入 LangGraph 自然语言补丁规划节点；工作流只自动应用 low 风险计划，中高风险计划先进入 LangGraph interrupt 确认状态，API/React 工作台已支持确认后 resume 应用或取消；结构化 planner schema 已支持 `rename_node`、`replace_constant`、`add_node_from_schema`、`connect`、`disconnect`、`enable_dynamic_input`、`copy_block` 和 `set_io_point`。
- LLM planner 已有基础与组合补丁评测样例和真实 DeepSeek 结构化规划测试；普通全量测试默认跳过真实 LLM 调用。
- LangGraph 已在进程内单例编译，默认接入内存 checkpointer；支持通过 `LANGGRAPH_CHECKPOINTER_BACKEND=postgres` 和 `DATABASE_URL` 创建 PostgreSQL checkpointer，并已完成 checkpoint 跨进程恢复和 interrupt/resume 集成验收；模板确认和中高风险补丁确认已使用 LangGraph 原生 interrupt，API 层保留兼容兜底。
- 规则 planner 仍是窄范围规则/正则实现，只适合明确目标的低风险补丁和少量需确认的中风险操作；复杂改造应使用显式开启的 LLM planner dry-run。
- 校验器已覆盖基础结构、拓扑引用、schema 参数合法性、动态端口一致性、IO/通讯冲突、机器可读保护逻辑规则库和补丁 dry-run 变更风险校验；保护规则当前偏保守，主要覆盖关键执行器无上游联锁、常量直连旁路、读写方向明显错误、保护信号停用、设备保护线索缺失、防冻保护链路缺失、保护节点删除和保护链路断线。
- 阶段7 React 工作台已推进到 7.8 第二段，FastAPI 根路径默认托管 `app/static/workbench/index.html`；旧静态原型保留在 `/legacy`。当前已具备项目类型选择、会话、澄清问题、模板确认、计划/dry-run 摘要、中高风险确认/取消、校验、导出检查、反馈提交和反馈历史、局部流程图、diff 分类定位、copy_block 边界预览、版本历史、版本对比、回滚确认、SSE 事件流连接状态、工作流步骤条、事件流抽屉、Trace 详情、Trace LLM/反馈/关键产物摘要、指标图表、LLM 成本聚合、观测趋势、两条真实浏览器主流程 E2E、组件级风险/校验/回滚测试和 1440px/390px 截图验收。
- 当前工程 JSON 的 `wires` 统一按 `input_sources` 语义理解：当前节点每个输入端保存上游源引用。

## 何时更新本文

需要更新：

- 新增、删除、重命名顶层目录或核心模块。
- `app/graph/` 工作流边界变化。
- `app/services/` 新增重要服务或拆分职责。
- 新增索引层级、schema 分类、知识库目录或 patch op。
- 运行时产物结构变化。
- 前端技术栈或目录迁移。
- 会话、项目、版本从文件/内存迁移到持久化存储。

不必更新：

- 普通 bug fix。
- 单个函数内部实现调整。
- 测试用例数量变化。
- README 中已有的运行命令或示例补丁变化。
