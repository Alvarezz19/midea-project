# 项目结构

更新时间：2026-04-28

用途：给 Codex 快速了解仓库结构和维护边界。本文只记录长期稳定的结构信息；详细运行方式、能力说明和路线规划分别看 `README.md`、`文档/生产级智能体系统改进方案.md`。

## 维护原则

- 只记录目录/模块职责、关键入口、运行时产物边界。
- 不展开 API 细节、测试断言、完整功能说明，避免文档膨胀。
- 结构变更后同步更新本文；普通业务逻辑小改不必更新。

## 顶层结构

```text
midea-project/
  app/                      后端、LangGraph 工作流、服务层、静态工作台
  pyproject.toml            Python 依赖与测试配置
  indexes/                  由 scripts/build_indexes.py 生成的检索索引
  knowledge/                Markdown 知识库：控制策略、工程规范
  migrations/               数据库迁移脚本
  evals/                    LLM planner 等评测样例
  programs/                 原始工程 JSON 模板库，不应被运行时覆盖
  projects/                 运行时工程版本输出
  rules/                    机器可读工程规则，当前包含保护逻辑规则
  schemas/                  模块 schema、节点生成模板和说明资料
  scripts/                  离线脚本
  tests/                    pytest 自动化测试
  文档/                     项目结构、演进、生产化方案等维护文档
    演进记录/               演进详细记录归档，按日期拆分
  README.md                 使用说明和当前能力概览
  AGENTS.md                 仓库级 Codex 说明
  智能体系统架构设计.md      架构设计文档
```

本地/缓存目录：`.codex/`、`.vscode/`、`.pytest_cache/`、`__pycache__/`、`.env`、日志文件等不作为业务结构维护。

## 核心代码

```text
app/
  main.py                   FastAPI 入口；API 路由；静态工作台托管
  core/
    config.py               环境变量配置入口
    logging.py              应用日志初始化
  graph/
    checkpointing.py         LangGraph checkpointer 后端选择
    state.py                AgentState 定义和初始状态
    nodes.py                LangGraph 节点、路由、摘要
    workflow.py             StateGraph 构建、单例编译和 invoke_workflow
  services/
    json_project.py         工程 JSON 读写、摘要、selector 查找、版本创建
    retrieval.py            模板/tab/功能块/节点索引检索和局部上下文加载
    knowledge.py            Markdown 知识分块和检索
    llm_gateway.py          LLM 供应商网关，默认 DeepSeek，预留 OpenAI/Azure/Anthropic
    llm_planner.py          LLM 结构化补丁规划，输出受 schema 约束的补丁意图
    planner_execution.py    LLM planner dry-run、失败反馈重试和尝试摘要的共享执行入口
    requirement_analysis.py 确定性结构化需求摘要、澄清问题和模板候选解释
    planner.py              规则型自然语言到结构化补丁规划
    patch_engine.py         结构化补丁执行
    project_diff.py         工程版本节点级 diff 摘要
    requirement_extractor.py LLM 结构化需求抽取
    schema_library.py       schema 加载、参数校验、节点生成
    runtime_store.py        运行时存储后端选择，默认 file，可切换 PostgreSQL
    postgres_runtime.py     PostgreSQL session、project/version、patch、validation、export、audit 运行时存储
    session_store.py        文件型会话状态存储和运行时存储工厂
    validator.py            工程 JSON 基础结构、schema、动态端口、IO/通讯、保护逻辑和变更风险校验
  static/
    index.html              原型工作台页面
    app.js                  前端交互和 API 调用
    styles.css              工作台样式
```

当前主流程：

```text
用户需求
  -> app/main.py
  -> app/graph/*
  -> requirement_analysis.py 确定性需求摘要与澄清问题
  -> requirement_extractor.py LLM 结构化抽取需求（显式 API 调用）
  -> app/services/retrieval.py / knowledge.py
  -> json_project.py 创建版本
  -> planner.py / llm_planner.py 规划补丁意图
  -> patch_engine.py 执行补丁
  -> validator.py 校验
  -> 导出 JSON
```

## 运行时产物

```text
projects/
  sessions/                 文件型会话状态输出目录
  versions/
    {project_id}/
      {version_id}.json
      {version_id}.meta.json 版本来源、父版本、hash、补丁摘要和校验摘要
```

`projects/versions/` 是默认版本输出目录。`RUNTIME_STORE_BACKEND=file` 时，会话状态写入 `projects/sessions/`；切换到 PostgreSQL 后，session 和版本元数据写入数据库，工程 JSON 文件本体仍保存在版本目录。测试应优先使用临时目录，避免污染真实运行时版本。

## 当前结构性限制

- 会话和版本运行时默认仍使用文件型存储；设置 `RUNTIME_STORE_BACKEND=postgres` 且配置 `DATABASE_URL` 后，session、project/version 元数据、patch、validation、export 和 audit 会写入 PostgreSQL，工程 JSON 文件本体仍保存在 `projects/versions/` 或配置目录。
- PostgreSQL 运行时存储和 LangGraph PostgreSQL checkpointer 已完成 Docker 本地集成验收；当前仍缺权限模型、运维查询和更细粒度审计检索等生产化配套。
- 补丁应用成功后会创建新的子版本并更新当前版本指针，不覆盖父版本 JSON。
- 回滚会把当前版本指针切回已有版本，版本目录中的历史文件不会删除。
- 补丁引擎支持 dry-run、节点级 diff 摘要、`replace_constant` 低风险常量/设定值替换、`enable_dynamic_input` 中风险动态输入端口启用、`copy_block` 高风险功能块复制和 `set_io_point` 高风险 IO/通讯点位修改；API 返回摘要，不返回完整工程节点数组。
- 项目版本支持按版本 ID 生成节点级 diff 摘要；前端尚未提供完整可视化。
- 导出接口会重新校验目标工程；存在 error 级阻塞问题时拒绝导出。
- 索引层级已包含功能块级 `blocks/block_index.jsonl`，支持局部功能块检索、按 `block_id` 加载预算受控的局部 JSON 上下文，以及 `copy_block` 第一版内部节点/内部连线复制；复制时会禁用复制节点上的本地 BACnet 暴露对象，避免复用原对象号。
- 工作流已接入确定性需求摘要和模板候选解释；当前会在项目类型或基本设备/控制目标不足时先进入澄清状态，通讯、保护逻辑和设备数量缺口会作为待确认问题展示。
- LLM Gateway 已接入 DeepSeek JSON 输出并预留 OpenAI、Azure OpenAI、Anthropic 配置入口；当前用于结构化需求抽取和显式开启的 LLM 结构化 planner dry-run，planner 支持 schema/dry-run 失败反馈重试，并已接入 LangGraph 自然语言补丁规划节点；工作流只自动应用 low 风险计划，中高风险计划先停在确认状态，API/静态工作台已支持确认后应用或取消；结构化 planner schema 已支持 `replace_constant`、`enable_dynamic_input`、`copy_block` 和 `set_io_point`。
- LLM planner 已有基础与组合补丁评测样例和真实 DeepSeek 结构化规划测试；普通全量测试默认跳过真实 LLM 调用。
- LangGraph 已在进程内单例编译，默认接入内存 checkpointer；支持通过 `LANGGRAPH_CHECKPOINTER_BACKEND=postgres` 和 `DATABASE_URL` 创建 PostgreSQL checkpointer，并已完成 checkpoint 跨进程恢复集成验收；高风险确认当前仍由状态/API 层模拟，尚未接入 LangGraph interrupt。
- planner 仍是规则/正则实现，只适合低风险补丁。
- 校验器已覆盖基础结构、拓扑引用、schema 参数合法性、动态端口一致性、IO/通讯冲突、机器可读保护逻辑规则库和补丁 dry-run 变更风险校验；保护规则当前偏保守，主要覆盖关键执行器无上游联锁、常量直连旁路、读写方向明显错误、保护信号停用、设备保护线索缺失、防冻保护链路缺失、保护节点删除和保护链路断线。
- 前端仍是静态原型工作台。
- 当前工程 JSON 的 `wires` 统一按 `input_sources` 语义理解：当前节点每个输入端保存上游源引用。

## 何时更新本文

需要更新：

- 新增、删除、重命名顶层目录或核心模块。
- `app/graph/` 工作流边界变化。
- `app/services/` 新增重要服务或拆分职责。
- 新增索引层级、schema 分类、知识库目录或 patch op。
- 运行时产物结构变化。
- 前端技术栈或目录迁移。
- 会话、项目、版本从文件/内存迁移到持久化存储。

不必更新：

- 普通 bug fix。
- 单个函数内部实现调整。
- 测试用例数量变化。
- README 中已有的运行命令或示例补丁变化。
