背景：ER-20260429-011 已让独立 planner、校验和导出 API 写入 trace/events，并让底部抽屉消费真实 `/metrics`。但 LLM 调用本身仍主要通过 `llm.*` 事件计数间接体现，缺少 `llm_call_records` 级别的数据源，Trace 页也没有展示 provider、model、prompt、token 和耗时等调用摘要。

目标：补齐阶段 7.7 的 LLM 调用记录底座。LLM planner 每次尝试都应形成可查询记录；file 后端和 PostgreSQL 后端都能保存；Trace 页能直接展示调用摘要；`/metrics` 使用真实 LLM 调用记录聚合调用数、失败数、token 和估算成本。本轮不调整 LLM prompt，不强制真实成本计费，拿不到价格时估算成本保持 0。

代码/契约变化：

- `app/services/llm_gateway.py`：
  - `chat_json()` 的 `_llm_meta` 增加 `prompt_name` 字段，默认 `chat_json`。

  - `/metrics` 改用 LLM 调用记录聚合 `midea_llm_calls_total`、失败数、输入 token、输出 token 和估算成本。

  - 工作流 update 回调和独立 planner API 从 `llm_meta` 落 LLM 调用记录。
