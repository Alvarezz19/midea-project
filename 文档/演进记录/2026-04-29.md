背景：阶段 7 方案要求先冻结 API 契约和事件模型，不先写页面。当前前端仍是静态原型，缺少 SSE 事件回放、trace 查询、反馈、metrics 和当前项目版本局部图接口。

目标：完成阶段 7.1 的最小可验收闭环，让后续 React 工作台有稳定契约可依赖，同时保持默认文件型运行方式兼容。

代码/契约变化：

- 新增 `文档/阶段7前后端契约.md`，固定公开会话状态字段、SSE 事件结构、续传规则、新增接口和局部流程图响应。
- `app/main.py` 新增：
  - `GET /api/sessions/{thread_id}/events`
  - `GET /api/projects/{project_id}/versions/{version_id}/flow`
  - `GET /api/traces/{trace_id}`
  - `GET /api/projects/{project_id}/traces`
  - `POST /api/feedback`
  - `GET /metrics`
- 会话创建、消息发送、模板确认恢复、补丁确认恢复、确认取消和确认应用会创建 trace 并写入基础 workflow event。
- `_public_state()` 新增 `project_id`、`version_id` 和 `validation_summary`，保留旧 `current_project_*` 字段兼容。
- 新增 `app/services/observability.py`：
  - file 后端写入 `projects/events/`、`projects/traces/`、`projects/feedback/`。
  - PostgreSQL 后端写入 `workflow_events`、`agent_traces`、`user_feedback`。
  - `/metrics` 输出基础 Prometheus 文本计数。
- 新增 `app/services/flow_graph.py`：
  - 按 `input_sources` 语义生成 React Flow 节点和边。
  - 支持 `center_node_id`、`max_nodes`、`max_edges`、`max_chars` 预算限制。
  - 不返回完整工程 JSON。
- 新增 `migrations/postgres/003_observability.sql`：
  - `workflow_events`
  - `agent_traces`
  - `llm_call_records`
  - `user_feedback`

影响：

- 前端可通过 SSE 按 `Last-Event-ID` 续传未消费事件。
- 开发者可通过 `trace_id` 查询单次请求链路。
- 工程版本局部图接口可作为 7.4 React Flow 渲染基础。
- PostgreSQL 可观测性 schema 已预留 LLM 调用、成本和用户反馈数据。
- 当前事件粒度只覆盖 API 主流程，尚未完整覆盖 LangGraph updates、LLM 调用、补丁执行和校验细粒度步骤。
