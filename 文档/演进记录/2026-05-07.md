### ER-20260507-001 前端候选选择和局部图定位

状态：已完成

修改人：Codex

关联文件：

- `frontend/src/features/session/SessionPanel.tsx`
- `frontend/src/features/planning/PlanningPanel.tsx`
- `frontend/src/features/graph/GraphPanel.tsx`
- `frontend/src/styles/panel.module.css`
- `frontend/src/features/session/SessionPanel.test.tsx`
- `frontend/src/features/planning/PlanningPanel.test.tsx`
- `frontend/src/features/graph/GraphPanel.test.tsx`
- `app/static/workbench/**`
- `文档/项目结构.md`
- `文档/演进记录.md`
- `文档/演进记录/2026-05-07.md`

背景：

Deadline 后智能体目标第 1 到第 3 天已让后端返回 `semantic_target_candidates`、`last_touched_entities` 和 `last_affected_node_ids`。前端仍需要把这些后端语义对象转成用户可理解的候选选择、修改后定位目标和局部图聚焦体验，避免用户面对裸 node id。

目标：

- 目标不唯一时，前端展示用户可读候选列表。
- 用户点击候选时，通过 `selected_candidate_id` 选择上一轮候选。
- 补丁成功后展示本次定位目标和影响对象。
- 局部图在 diff 暂不可用或为空时，仍可用 `last_affected_node_ids` 聚焦被改节点。

代码/契约变化：

- 会话面板在 `next_action=clarify_patch` 时显示“请选择目标对象”，候选项展示页面、类型、描述、关键参数和置信度，不展示内部 selector id。
- 点击候选会发送自然语言“选择第 N 个：...”并携带隐藏字段 `selected_candidate_id`。
- 计划面板新增“语义定位”区域，展示候选对象和 `last_touched_entities`。
- 图面板优先使用 diff affected 节点；当 diff 为空时回退使用 `last_affected_node_ids`，并用 `last_touched_entities` 的可读名称替代裸 id。
- 补充候选卡片、定位对象和移动端布局样式。

影响：

- 用户在模糊表达“把比较判断改名为 xxx”后，可以直接点击候选，不需要输入节点 ID。
- 修改成功后，用户能看到系统实际定位到的业务对象。
- 局部图对低风险自动应用、dry-run 或 diff 尚未返回的场景更稳。

验证：

```powershell

cd frontend
npm run lint
npm run test -- --run src/features/session/SessionPanel.test.tsx src/features/planning/PlanningPanel.test.tsx src/features/graph/GraphPanel.test.tsx --reporter=dot
npm run test -- --run --reporter=dot
npm run build
```

结果：

```text
定向组件测试：13 passed
npm run lint：通过
npm run test：33 passed
npm run build：通过
```

风险/回滚：

- 候选选择只在 `clarify_patch` 状态显示，避免补丁已完成后仍误导用户选择旧候选。
- 回滚时可移除前端新增展示和 `selected_candidate_id` 调用，后端自然语言“第 1 个”选择仍可工作。

文档同步：

- `文档/演进记录.md` 和本归档已同步。

后续动作：

DoD：

### ER-20260507-002 语义工作流评测和回归修复

状态：已完成

修改人：Codex

关联文件：

- `evals/semantic_workflow_cases.jsonl`
- `tests/test_semantic_workflow_evals.py`
- `app/services/semantic_locator.py`
- `app/services/planner_execution.py`

- `tests/test_llm_gateway.py`

- `文档/演进记录.md`
- `文档/演进记录/2026-05-07.md`

背景：

第 6 天目标要求“用测试证明能力，而不是只靠演示”。现有测试已覆盖部分语义定位和工作流行为，但缺少一份面向用户场景的集中评测清单；同时需要如实跑回归，暴露并修复潜在问题。

目标：

- 新增语义工作流评测样例，覆盖无 ID 改名、无 ID 改阈值、刚才那个节点、多候选、选择第 1 个、CO2 候选澄清。
- 对 CO2 接线、旁通阀压差接线和 IO 点位修改保留 reference patch plan dry-run 验证，不把非确定性 LLM 输出伪装成稳定通过。
- 跑全量后端和前端回归，并记录真实结果。

代码/契约变化：

- 新增 `evals/semantic_workflow_cases.jsonl`：
  - `workflow_patch`：真实工作流用户输入。
  - `workflow_clarification`：候选和追问验证。
  - `reference_patch_plan`：复用 `patch_planning_cases.jsonl` 的 golden plan 做 dry-run。
- 新增 `tests/test_semantic_workflow_evals.py`，统一执行上述评测。
- `semantic_locator.py` 修复：
  - 显式节点 ID 优先解析，避免“节点 67febfa 的常量值”被按“常量”扩成多候选。
  - 支持“控制页面/控制页/控制页签”匹配页签“控制”。
  - 名称线索过窄但页面或类型已匹配时，退回页面/类型候选而不是空结果。
- `planner_execution.py` 在 LLM 输出进入 patch engine 前，归一化 `constInput` 常见参数别名：
  - `name/label` -> `user_defined_name`
  - `value/fixed_value` -> `fixedValue`

真实发现的问题：

- 业务验收 `test_business_acceptance_parameter_patch_diff_and_flow_focus` 一度失败，状态从 `patch_applied` 变为 `awaiting_patch_clarification`；根因是 semantic locator 没有优先处理显式节点 ID。已修复。
- 真实探测“新增旁通阀压差设定并接入比较判断”时，LLM fallback 曾输出 schema 不接受的 `label/value` 参数，dry-run 失败后进入澄清。已在 LLM 边界归一化参数别名。
- CO2 自然语言接线当前稳定行为是返回用户可读候选，不直接自动应用；CO2 接线能力通过 reference patch plan dry-run 证明，不声称自然语言自动接线已完全通过。

影响：

- 第 6 天能力证明从零散单测变成可重复评测文件。
- 显式节点 ID 兼容性恢复，旧式高级输入不会被语义候选链路破坏。
- LLM 常见 schema 别名错误可在系统边界被吸收，减少不必要的 dry-run 失败。
