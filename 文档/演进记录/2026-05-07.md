背景：

Deadline 后智能体目标第 1 到第 3 天已让后端返回 `semantic_target_candidates`、`last_touched_entities` 和 `last_affected_node_ids`。前端仍需要把这些后端语义对象转成用户可理解的候选选择、修改后定位目标和局部图聚焦体验，避免用户面对裸 node id。

目标：

- 目标不唯一时，前端展示用户可读候选列表。
- 用户点击候选时，通过 `selected_candidate_id` 选择上一轮候选。

- 局部图在 diff 暂不可用或为空时，仍可用 `last_affected_node_ids` 聚焦被改节点。

- 计划面板新增“语义定位”区域，展示候选对象和 `last_touched_entities`。
- 图面板优先使用 diff affected 节点；当 diff 为空时回退使用 `last_affected_node_ids`，并用 `last_touched_entities` 的可读名称替代裸 id。
- 补充候选卡片、定位对象和移动端布局样式。

影响：

- 用户在模糊表达“把比较判断改名为 xxx”后，可以直接点击候选，不需要输入节点 ID。
- 修改成功后，用户能看到系统实际定位到的业务对象。
- 局部图对低风险自动应用、dry-run 或 diff 尚未返回的场景更稳。

### ER-20260507-003 咨询/设计建议 P0 分支和真实 LLM 契约优化

修改人：Codex

关联文件：

- `文档/演进记录.md`
- `文档/演进记录/2026-05-07.md`

背景：

创建工程版本后，用户输入默认进入局部补丁规划；“把送风温度设定值改为多少比较好？”这类咨询会被“改为、设定值”等词误判成潜在补丁请求。需要新增 P0 咨询/设计建议分支，在不绕过现有 semantic locator、planner、dry-run、风险确认、校验和导出门禁的前提下，支持工程咨询、候选需求沉淀和用户明确采纳后的受控补丁流程。

目标：

- 已建工程后的咨询问题不生成 `pending_patch`，不创建新版本。
- 咨询回答结合本地知识和当前工程上下文，输出结构化 `advisory_result`。
- 用户“采纳建议”时，只把 `adoptable_patch_intent.message` 转回现有 planner 链路，不直接落盘修改。
- 用户“先不改”时，清理待采纳建议，工程版本不变。
- 无关问题返回 `out_of_scope`，不写候选需求。
- 真实 LLM 下稳定区分“咨询是否可回答”和“补丁是否可执行”。

代码/契约变化：

- 新增 `advisory_intent.py`：
  - 规则 + LLM 意图路由，识别 `advisory_intent`、`patch_intent`、`advice_acceptance`、`advice_override`、`advice_rejection`、`domain_question`、`out_of_scope` 和 `uncertain`。
  - 优先处理上一轮 `pending_advice` 的采纳、覆盖采纳和拒绝语义。
- 新增 `advisory.py`：
  - 多路 query 检索知识库、工程规范和当前工程摘要。
  - 咨询主知识上下文不混入 `knowledge/补丁配方.md`；补丁配方单独放入 `patch_support_context`，只用于判断能否形成可采纳修改意图。
  - LLM prompt 明确拆分 `status` 和 `adoptable_patch_intent.executable`：找不到节点或缺接线位置不能把典型工程咨询降级为 `needs_more_info`。
  - `_repair_advisory_result()` 保留真实 LLM 回答、依据和风险，只修正“咨询已可回答但补丁不可执行”的结构化状态。
  - normalizer 强制回答包含“当前不会修改工程”，避免用户误解。
- `AgentState` 新增：
  - `advisory_result`
  - `pending_advice`
  - `advice_history`
  - `advice_context_summary`
  - `candidate_requirements`
- `plan_patch_node` 前置拦截咨询/采纳/拒绝：
  - 咨询直接返回 `advisory_answered`、`advisory_needs_more_info`、`advisory_unsafe_request` 或 `advisory_out_of_scope`。
  - 采纳建议后用明确修改消息继续走现有 semantic locator、规则 planner、LLM planner fallback、dry-run 和确认链路。
  - 拒绝建议不创建版本、不写补丁。
- `_public_state()` 暴露咨询字段。
- 前端 `PlanningPanel` 新增“设计建议”展示区：
  - 展示推荐、依据、前提、风险、缺失信息和候选需求数量。
  - 提供“采纳并生成修改计划”“纳入候选需求”“暂不采用”按钮，继续复用 message API。

真实发现的问题：

- 真实 DeepSeek 初次回答“送风温度设定值多少比较好”时，曾因缺少目标节点把结果降为 `needs_more_info`，但回答正文已给出典型范围和风险。根因是 LLM 把“补丁不可执行”误当成“咨询不可回答”。
- 已通过 prompt 契约拆分、补丁配方检索降噪和结构化输出修正解决；修正后真实工作流返回 `advisory_answered`，`advisory_result.status=answered`，且 `pending_patch=None`。

影响：

- 普通用户可以先咨询工程参数、保护逻辑和设计取舍，不会因为“改为/设定值”等词被误触发补丁。
- 咨询内容可作为候选需求沉淀，但未确认前不进入正式需求槽位和导出门禁。
- 采纳建议后仍复用既有受控修改链路，不扩大工程 JSON 写入边界。
- 前端把咨询建议和补丁计划分开展示，降低用户误解风险。

目标：

- `create_project_version` 后先进入独立 `route_user_intent` 节点。

- 保护、联锁、防冻删除类咨询输出 `unsafe_request`，不形成可执行补丁。

- `AgentState` 新增 `user_intent_route`，用于公开本轮意图路由结果、原始输入、采纳后的明确修改消息、意图分类和上下文摘要。

  - `route_user_intent`
  - `advisory_chat`
- `create_project_version` 后的条件路由改为：

```text
create_project_version
  -> route_user_intent
    -> advisory_chat
    -> plan_patch
    -> summarize_result
```

- `nodes.py` 新增：
  - `route_user_intent_node`
