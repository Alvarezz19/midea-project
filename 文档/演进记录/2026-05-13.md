背景：

此前补丁规划评测中使用过节点 ID 型问题，但普通用户并不知道 `795dbc3`、`67febfa` 这类内部节点 ID。用户要求改用真实 LLM 和用户视角问题重新测试 `rename_node`、`replace_constant`、`add_tab`、`add_node_from_schema`、`connect`、`disconnect`、`enable_dynamic_input`、`copy_block`、`set_io_point` 等补丁操作。真实 DeepSeek 测试暴露出三类主要问题：LLM 对简单动态输入请求会擅自新增节点和连线，输入序号断线会猜测源节点，纯新增节点会被语义候选干扰；另外发现 `copy_block` 多候选时容易猜测 block，以及无变化 dry-run 可能被误认为有效计划。

目标：

- 让补丁规划测试和验收问题尽量贴近普通用户表达，不要求用户提供裸节点 ID。
- 在 LLM 输出进入 patch engine 前补齐服务边界后处理，降低模型幻觉操作带来的执行风险。
- 确保无变化 dry-run 进入失败反馈重试，而不是被当作有效补丁。
- 记录真实 LLM 验收覆盖的问题和仍需后续处理的边界。

代码/契约变化：

- `llm_planner.py` 增强 prompt 约束：
  - 用户只要求启用动态输入时，只能输出 `enable_dynamic_input`，不得擅自新增节点、软件输入、常量或连线。
  - 用户只说断开某个输入端时，按用户序号归一化为零基 `target_input`，不猜测 `source_node_selector`。
  - `related_blocks` 存在多个候选且用户没有明确标题时，`copy_block` 必须追问，不猜测 `block_id`。
- `llm_planner.py` 新增服务边界后处理：
  - 简单动态输入请求只保留 `enable_dynamic_input` 操作。
  - 输入序号断线移除猜测的源节点和源端口，并把“第 N 个输入”转为零基 `target_input`。
  - 纯新增常量、软件输入、设定值、PID 等请求不再让现有语义候选强行变成目标节点。
  - 多功能块候选复制请求改为 `needs_clarification`，并返回候选标题。
- `planner_execution.py` 将 `dry_run["valid"]` 但 `changed is False` 的计划视为失败，反馈给 LLM 重试。
- `patch_engine.py` 让无实际移除连线的 `disconnect` 抛出 `PatchEngineError`，避免 no-op 断线进入成功路径。
- `planner.py` 修复 `add_tab` 在句尾中文或英文标点下的页面名识别。
- `tests/test_llm_gateway.py` 和 `tests/test_services.py` 补充上述边界的单元和服务层回归测试。

影响：

- 普通用户可以继续用页面名、节点语义、输入序号、功能块标题等自然语言描述修改目标，系统不应要求用户提供内部节点 ID。
- LLM planner 的输出更保守，复杂或含多个候选的 `copy_block` 会先追问，避免复制错误功能块。
- no-op 补丁不再被误判为有效计划，有助于真实 LLM 失败反馈重试。
- 本轮没有新增 patch op，没有改变 LangGraph 工作流边界，也没有改变前端契约。
