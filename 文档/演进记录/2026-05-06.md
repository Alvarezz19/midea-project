背景：

2026-05-06 17:43:31 提交 `eefb668` 新增了 `add_tab` 补丁能力，但当时只同步了 README 和部分项目结构说明，演进记录未更新。该能力用于把“新增一个 CO2 控制页面”这类明确低风险需求转成结构化补丁，不从零生成页面内完整控制逻辑。

目标：

- 允许结构化补丁新增空页面/tab 节点。
- 规则 planner 能识别明确的新建页面自然语言。
- LLM planner schema 和 prompt 明确允许 `add_tab`。
- 风险摘要和前端计划预览能以业务语言展示“新增页面”。
- 保持所有工程 JSON 修改仍由 patch engine 执行，后续新增节点、复制功能块或接线继续走对应 op 和风险确认。

代码/契约变化：

- `patch_engine.py` 新增 `add_tab` 执行分支：
  - 支持 `{"op": "add_tab", "label": "CO2 控制"}`。
  - 创建 `type="tab"` 节点，写入 `label`、`disabled`、`info`。
  - 默认拒绝重复页面标签，除非显式设置 `allow_duplicate_label=true`。
  - dry-run 返回新增节点 diff 和 `changes` 摘要。
- `planner.py` 新增规则规划：
  - 可识别“新增、添加、创建、新建 + 页面/页签/tab”的明确请求。
  - 对缺少页面名称或标签重复的场景返回面向用户的追问。
  - 避免把“在某页面里新增某内容”误判为新建页面。
- `llm_planner.py`：
  - `PatchOp`、`PlannedOperation` schema 和 prompt 均允许 `add_tab`。
  - 明确 `add_tab` 只新增空页面，不自动创建功能节点或连线。
  - 新增空页面通常标记为 low risk。
- `app/graph/nodes.py`：
  - 操作摘要支持 `add_tab`，显示“新增页面：xxx”。
- `PlanningPanel.tsx`：
  - 前端计划预览将 `add_tab` 显示为“新增页面”，并展示页面标签。
- `文档/deadline前智能体目标实现方案.md`：
  - 将当前底座能力更新为包含 `add_tab`。

影响：

- 用户可直接输入“新增一个 CO2 控制页面”，系统生成低风险 `add_tab` 补丁并可自动应用。
- 新页面只是空页面，不代表已经生成 CO2 控制逻辑。
- 如后续要在页面内新增模块、复制功能块或接线，仍需要 `add_node_from_schema`、`copy_block`、`connect` 等操作，并按中高风险策略 dry-run 和确认。

### ER-20260506-002 当前工程语义索引、工作记忆、语义定位器和 context-aware LLM planner

状态：已完成

修改人：Codex

关联文件：

- `文档/演进记录.md`
- `文档/演进记录/2026-05-06.md`

背景：

`文档/deadline前智能体目标实现方案.md` 指出创建工程后的多轮修改阶段仍要求用户提供内部节点 ID，根因是 planner 缺少当前工程版本的语义索引、工作记忆和语义定位链路。用户真实表达通常是“水泵控制里的比较判断”“刚才那个节点”“旁通阀那边”，系统需要先在当前 JSON 中自行定位，再生成结构化补丁并 dry-run。

目标：

- 建立当前工程语义索引，检索结果必须反映当前子版本，而不是离线模板索引。
- 在 `AgentState` 中保存创建版本后的工作记忆，尤其是最近 affected 节点和最近触达实体。
- 新增语义定位器，把页面、节点类型、业务关键词和“刚才那个节点”解析为候选 selector。
- LLM planner 消费语义定位、当前工程候选、节点邻域和工作记忆，复杂改造时按上下文规划，不要求用户提供节点 ID。

代码/契约变化：

- 新增 `project_semantic_index.py`：
  - 从 `current_project_path` 对应 JSON 现扫构建 `tabs`、`nodes`、`by_tab`、`by_type`。
  - 节点摘要包含页面、类型、名称、关键参数、输入源、上下游摘要、schema 关联和 role hints。
  - 提供 `search_current_project_nodes()`、`summarize_current_project_for_planner()`、`summarize_affected_nodes()`。
- 扩展 `AgentState` 和 API 公开状态：
  - `conversation_summary`
  - `recent_user_intents`
  - `last_affected_node_ids`
  - `last_touched_entities`
  - `last_patch_summary`
  - `semantic_target_candidates`
- `apply_pending_patch_node` 在补丁成功并创建子版本后更新工作记忆；助手摘要会展示本次定位目标。
- 新增 `semantic_locator.py`：
  - 支持页面 + 节点类型唯一定位，例如“水泵控制里的比较判断”。
  - 支持最近节点引用，例如“刚才那个节点”。
  - 多候选时返回用户可读候选，不把普通用户追问引向节点 ID。
- `planner.py` 增加 `semantic_location` 可选入参：
  - 规则 planner 可直接使用定位器提供的 selector。
  - 追问文案改为页面、节点名称或业务对象。
- `llm_planner.py` 增加 context-aware 入参：
  - `conversation_context`
  - `target_resolution`
  - `current_project_context`
  - prompt 中加入 `current_project_nodes`、`node_neighborhoods`、`related_blocks` 和 block context。
  - prompt 明确节点 ID 只能来自系统上下文，禁止要求用户提供节点 ID。
- `planner_execution.py` 在 dry-run feedback 重试时持续传递上述上下文。
- `nodes.py` 在 LLM fallback 时传入工作记忆和语义定位结果，并兼容测试中旧 fake planner 签名。

影响：

- 用户可以输入“把水泵控制里的比较判断改名为 演示节点”，后端定位到当前工程 `3a4c97e` 并生成 `rename_node`。
- 用户第二轮输入“把刚才那个节点的阈值改为 3”，后端可使用 `last_affected_node_ids` 定位最近节点，并按现有风险策略进入确认。
- 如果用户只说“把比较判断改名为 xxx”，后端返回候选列表，候选包含页面、类型、名称、关键参数和上下游摘要。
- LLM planner 不再只看模板索引；已改名、新增或复制后的当前版本状态可以进入 prompt。
