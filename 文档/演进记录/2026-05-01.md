背景：

`文档/deadline前智能体目标实现方案.md` 将第 1 天目标定为“修复基线和需求槽位归一化”。当时主流程已经有确定性需求摘要和 LLM 需求抽取服务，但二者字段未统一，主工作流仍主要依赖规则摘要；前端也存在 `control_targets/protections` 与后端 `control_features/protection_logic` 的字段错位，以及模板改造成本 `reason/reasons` 展示错位。

目标：

- 修复当前测试基线和前后端字段契约错位。
- 新增 `RequirementSlots` 归一化层，作为规则抽取和 LLM 抽取的统一汇入点。
- 保持主流程既有 `requirement_summary/open_questions/confirmed_requirements` 兼容字段。
- 支持多轮需求累计、数量覆盖和否定语义。
- 已创建工程版本后，用户局部修改请求不重新进入新工程模板澄清。

代码/契约变化：

- 新增 `app/services/requirement_model.py`：
  - `merge_requirement_slots()` 合并规则摘要、LLM 抽取结果和历史槽位。
  - `requirement_summary_from_slots()` 从槽位派生主流程兼容摘要。
  - 槽位记录 `project_type`、`task_type`、`equipment`、`control_features`、`communication`、`io_points`、`protection_logic`、`design_constraints`、`missing_fields`、`risk_level`、`risk_items`、`message_history`、`slot_sources` 和 `slot_status`。
  - 支持“改成、调整为、不是、不要、取消、不需要、改为”等覆盖或否定语义。
  - 支持设备数量抽取和数量变化风险标记。
  - LLM 不可用时不影响规则路径。
- `app/graph/state.py`：
  - `AgentState` 新增 `requirement_slots`、`design_brief`、`conformance_report`。
- `app/graph/nodes.py`：
  - `collect_requirements` 先执行 `analyze_requirement()`，再尝试 `extract_requirement_with_llm()`，最后合并到 `RequirementSlots`。
  - LLM 抽取失败捕获为规则回退，不抛出到工作流。
  - 已有工程版本时，槽位 `task_type` 进入 `modify_existing`，路由继续进入补丁规划。
- `app/main.py`：
  - `_empty_state()` 和 `_public_state()` 公开/保存 `requirement_slots/design_brief/conformance_report`。
- 前端契约：
  - `RequirementSummary` 改为读取 `control_features/protection_logic/io_points`。
  - `TemplateCandidate.estimated_modification_cost` 支持后端返回的 `reasons` 数组。
  - `SessionPanel` 正确展示后端结构化需求字段。
  - `PlanningPanel` 正确展示改造成本原因数组。
- 测试：
  - 新增 `tests/test_requirement_model.py`，覆盖 AHU/机房群控抽取、模糊追问、设备数量覆盖、排风机否定、LLM 合并和已有工程修改路由。
  - 更新 `tests/test_workflow_api.py` 的 React 工作台标题断言。
  - 新增前端组件契约测试，防止字段错位回归。
- 重新构建 `app/static/workbench/`。

影响：

- 主工作流不再直接让 LLM 输出替换 `requirement_summary`，而是统一经槽位层派生兼容字段，降低状态兼容风险。
- 用户第一轮说“2 台水泵”，后续说“水泵改成 3 台”，当前有效需求为 3 台，旧数量保留为来源/覆盖信息但不作为有效需求展示。
- 用户第一轮说“需要排风机”，后续说“不要排风机”，排风机槽位标记为 `rejected`，不再出现在当前有效需求中。
- 用户只说“我要做控制程序”仍追问项目类型；只说“我要做 AHU”仍追问主要设备或控制目标。
- 已创建工程后，局部改名、常量修改等请求不会因为缺少完整新工程槽位被误拦截。

背景：

目标：

- 新建会话默认启用 LLM 结构化规划。

- `frontend/src/store/workbenchStore.ts`：
  - Zustand 初始 `useLlmPlanner` 改为 `true`。
  - `setSession()` 从后端状态回填时，缺省值改为 `true`。
- `tests/test_workflow_api.py`：
  - API 端到端测试新增断言：创建会话默认 `use_llm_planner` 为 `true`。
- 重新构建 `app/static/workbench/`。

影响：

- 新会话默认走 LLM planner 能力开关；如果 LLM 不可用，已有 planner 节点仍返回澄清/不可用提示，不应报 500。
- 前端开关仍可手动关闭，并通过 `createSession()`、`sendMessage()` 传回后端。
- 已有旧会话状态如果明确保存了 `use_llm_planner=false`，仍会按旧会话状态关闭。

`文档/deadline前智能体目标实现方案.md` 将第 5 天目标定为“变更可视化和前端 E2E”。此前右侧局部流程图已经能加载预算受控 React Flow 摘要、显示 diff 分类和 `copy_block` 边界预览，但仍更像普通摘要图：默认不会自动聚焦本次变更节点，节点样式只区分“受影响”，无法直观看到新增、修改、删除和风险节点；dry-run 中尚未落盘的新增/删除节点也不容易在图上理解。用户提供的 KONG 画布截图要求当前阶段不做完整编辑器，但要让工程师像看工程画布一样判断本次修改影响范围。

目标：

- 增强局部流程图 diff 高亮和 affected nodes 自动定位。
- 支持修改前、修改后、diff 高亮三种查看模式，第一版以 diff 高亮和定位为主。
- 按 tab/page 过滤展示，优先展示当前补丁涉及页面，不拉取完整工程 JSON。
- 用稳定颜色区分新增、修改、删除和中高风险节点/连线。
- 对 dry-run 未落盘的新增/删除节点提供预览，避免确认前只能看补丁 JSON。
- 展示 `copy_block` 边界预览、复制节点范围和边界接线摘要。
- 展示 `set_io_point` 点位字段前后变化。
- 节点样式贴近 KONG 画布观感：网格背景、矩形节点、端口、连线、页签和节点类型色块，但不提供拖拽编辑和手工接线能力。
- Playwright 覆盖完整工作台流程，并验证修改后局部图自动定位。

代码/契约变化：

- `app/services/flow_graph.py`：
  - `build_react_flow()` 新增 `focus_node_ids` 和 `tab_id` 参数。
  - 候选节点选择改为优先包含 focus/center 节点，再包含其上游、下游和相关页签节点，最后才按预算补充其它节点。
  - 返回 `tabs` 列表，供前端做页签过滤。
  - 继续保持 `max_nodes/max_edges/max_chars` 预算，不返回完整工程 JSON。
- `app/main.py`：
  - `/api/projects/{project_id}/versions/{version_id}/flow` 新增 `focus_node_ids` 和 `tab_id` 查询参数，并透传到 `build_react_flow()`。
- 前端 API 契约：
  - `getProjectFlow()` 支持 `{ centerNodeId, focusNodeIds, tabId }`。
  - `ProjectFlowResponse.flow.tabs` 暴露页签列表。
  - `FlowNodeData` 扩展 `affected/diff_kind/risk` 只读展示字段。
- `GraphPanel.tsx`：
  - 本地优先使用 `patch_result.diff` 或 `planner_dry_run.diff`，没有本地 diff 时再读版本 diff。
  - 自动把第一个 affected node 作为 `centerNodeId`，并将 affected node ids 作为 `focus_node_ids` 请求后端局部图。
  - 新增“修改前 / 修改后 / diff 高亮”分段控件。
  - 新增页签过滤按钮，按 `tab_id` 请求预算受控局部图。
  - 用绿色、橙色、红色分别标识新增、修改、删除节点；中高风险节点/连线用警示样式。
  - 对 dry-run 中未落盘的新增/删除节点生成合成预览节点，对新增连线生成预览边。
  - 保留 diff 分类列表和 affected chips，点击后更新定位节点。
  - 保留并强化 `copy_block` 边界预览。
- `PlanningPanel.tsx`：
  - 操作摘要补充 `params` 简要展示。
  - 新增 `set_io_point` 字段前后变化列表。
  - 新增 `copy_block` 复制节点数、丢弃外部入口线、边界接线数摘要。
- `panel.module.css`：
  - 局部图背景改为工程图网格。
  - 节点改为更接近 KONG 画布的矩形形态，带节点类型色块、端口、diff 状态边框和风险标记。
  - 新增页签条、diff 状态和风险节点样式。
- 测试：
  - `GraphPanel.test.tsx` 覆盖 affected 节点自动定位、预算局部图请求带 `focus_node_ids`、dry-run 新增节点预览和 IO 风险变更展示。
