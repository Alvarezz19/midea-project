# 阶段7前后端契约

更新时间：2026-04-29

用途：冻结阶段 7 React 工作台依赖的后端公开字段、事件模型和新增接口。本文只记录前端可依赖的契约；内部服务实现可迭代，但不得破坏这里列出的字段语义。

## 1. 公开会话状态

所有会话主流程接口至少返回：

```json
{
  "thread_id": "thread_...",
  "trace_id": "trace_...",
  "state": {
    "status": "project_version_ready",
    "next_action": "send_message",
    "project_id": "project_...",
    "version_id": "v_...",
    "validation_summary": {
      "valid": true,
      "exportable": true,
      "error_count": 0,
      "warning_count": 0,
      "risk_count": 0,
      "blocked_export_reasons": []
    },
    "risk_assessment": {
      "risk_level": "low",
      "requires_confirmation": false,
      "reasons": []
    }
  }
}
```

兼容字段 `current_project_id`、`current_project_version_id`、`current_project_path` 暂时保留，前端新代码优先使用 `project_id` 和 `version_id`。

## 2. SSE 事件结构

`GET /api/sessions/{thread_id}/events` 返回 `text/event-stream`。每条事件：

```json
{
  "event_id": "evt_...",
  "trace_id": "trace_...",
  "thread_id": "thread_...",
  "project_id": "project_...",
  "version_id": "v_...",
  "event_type": "workflow.run.completed",
  "step": "invoke_workflow",
  "status": "project_version_ready",
  "message": "工作流执行完成",
  "payload": {},
  "created_at": "2026-04-29T10:00:00+08:00"
}
```

续传规则：

- 前端断线重连时传 `Last-Event-ID` 请求头。
- 后端只返回该事件之后尚未消费的事件。
- 如果事件 ID 不存在，file 后端回放当前会话全部事件，PostgreSQL 后端按最早事件开始返回。
- 前端必须按 `event_id` 去重。

## 3. 新增接口

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/sessions/{thread_id}/events` | GET | SSE 事件流，支持 `Last-Event-ID` 和 `last_event_id` 查询参数 |
| `/api/projects/{project_id}/versions/{version_id}/flow` | GET | 返回预算受控的 React Flow 节点和边 |
| `/api/traces/{trace_id}` | GET | 查询一次请求链路 |
| `/api/traces/{trace_id}/feedback` | GET | 查询单次 trace 的用户反馈 |
| `/api/projects/{project_id}/traces` | GET | 查询项目 trace 列表 |
| `/api/projects/{project_id}/feedback` | GET | 查询项目用户反馈列表 |
| `/api/feedback` | POST | 提交用户反馈 |
| `/metrics` | GET | Prometheus 文本指标 |

## 4. 局部流程图接口

请求参数：

- `center_node_id`：可选；传入后优先返回中心节点、上游输入源、直接下游节点。
- `max_nodes`：默认 80，最大 300。
- `max_edges`：默认 160，最大 800。
- `max_chars`：默认 120000，最大 500000。

响应只返回 React Flow 所需摘要，不返回完整工程 JSON：

```json
{
  "project_id": "project_...",
  "version_id": "v_...",
  "flow": {
    "nodes": [
      {
        "id": "node_id",
        "type": "engineeringNode",
        "position": {"x": 100, "y": 200},
        "data": {
          "label": "节点名称",
          "module_type": "compare",
          "role": "compare",
          "tab_id": "tab_id",
          "tab_label": "水泵控制",
          "inputs": 2,
          "outputs": 1
        }
      }
    ],
    "edges": [
      {
        "id": "edge_...",
        "source": "source_node",
        "target": "target_node",
        "sourceHandle": "out-0",
        "targetHandle": "in-0",
        "data": {"semantic": "input_sources"}
      }
    ],
    "budget": {
      "max_nodes": 80,
      "max_edges": 160,
      "max_chars": 120000,
      "node_count": 20,
      "edge_count": 35,
      "truncated": false
    }
  }
}
```

边方向固定为：上游源节点 `source` 指向当前节点输入端 `target`。

## 5. 可观测性存储

file 后端本地兼容路径：

```text
projects/
  events/{thread_id}.jsonl
  traces/{trace_id}.json
  feedback/user_feedback.jsonl
```

PostgreSQL 后端使用迁移 `migrations/postgres/003_observability.sql` 中的表：

- `workflow_events`
- `agent_traces`
- `llm_call_records`
- `user_feedback`

## 6. 当前边界

- 当前 SSE 已支持事件回放和续传，后续 7.6 再把 LangGraph `updates`、LLM 调用、补丁执行和校验细粒度步骤全部写入事件流。
- 当前 `/metrics` 输出基础计数指标，后续 7.7 再补 P95 延迟、token、成本、失败率等聚合指标。
- 局部图接口只返回摘要字段；前端不得依赖完整节点对象。
