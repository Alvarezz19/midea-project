# 阶段7生产前端与可观测性实施方案

更新时间：2026-04-29

适用范围：本文只固定 `文档/生产级智能体系统改进方案.md` 中“阶段 7：生产前端与可观测性”的落地顺序、技术栈、界面设计和验收口径。鉴权、权限、CORS、HTTPS、限流、备份恢复和生产部署手册仍归入阶段 8。

## 1. 阶段目标

阶段 7 的目标固定为两句话：

1. 工程师可真实使用：完整流程从新建会话、选择项目类型、澄清需求、确认模板、提出改造、预览计划、确认风险、校验、版本对比、回滚到导出，都不需要手写补丁 JSON。
2. 开发者可定位问题：每次修改都能追踪到用户输入、LangGraph 步骤、LLM 尝试、结构化计划、补丁、dry-run、diff、校验、确认、版本提交、导出和用户反馈。

阶段 7 不改变既有核心原则：

1. 工程 JSON 修改必须继续通过结构化补丁和校验服务。
2. 高风险操作必须继续走 LangGraph interrupt 确认。
3. 前端不得绕过后端直接改工程 JSON。
4. 不把完整工程 JSON 长期放入前端状态、Graph state 或 prompt。
5. 有 error 级阻塞问题时仍拒绝导出。

## 2. 当前基础

已可复用能力：

| 能力 | 当前状态 | 阶段 7 用法 |
| --- | --- | --- |
| 会话与工作流 | `/api/sessions`、`/api/sessions/{thread_id}/message` | React 工作台主流程入口 |
| 模板确认 | LangGraph 原生 interrupt + API 兼容兜底 | 模板候选卡片确认 |
| 中高风险补丁确认 | `/api/sessions/{thread_id}/patch-confirmation` | 风险确认面板 |
| 版本历史 | `/api/projects/{project_id}/versions` | 版本时间线 |
| 版本 diff | `/api/projects/{project_id}/diff` | diff 摘要、节点影响面板 |
| 回滚 | `/api/projects/{project_id}/rollback` | 版本历史中的回滚动作 |
| 校验 | `/api/projects/{project_id}/validate` | 校验报告 UI 和导出检查 |
| 导出 | `/api/projects/{project_id}/export` | 只在可导出时启用 |
| 功能块检索 | `/api/blocks/search`、`/api/blocks/context` | 局部流程图和 copy_block 边界确认 |
| 运行时存储 | file 默认，PostgreSQL 可选 | 可观测性优先写 PostgreSQL，file 保持本地兼容 |

主要缺口：

1. 前端仍是 `app/static/*` 静态原型，缺少生产级工程工作台。
2. 局部图只具备后端检索和上下文能力，缺少面向当前项目版本的图渲染接口。
3. 工作流没有统一事件流，用户看不到节点级进度。
4. trace、指标、成本和用户反馈没有统一数据模型和查询入口。
5. 开发者排障仍依赖日志和测试，缺少按 `thread_id/project_id/version_id/trace_id` 串联的调试视图。

## 3. 技术栈固定

### 3.1 前端

| 分类 | 固定选择 | 用途 |
| --- | --- | --- |
| 构建 | Vite + React + TypeScript | 阶段 7 工作台源码和构建 |
| UI 组件 | Ant Design 5 + 自定义 Design Token | 企业级表格、表单、抽屉、确认框、标签、步骤条 |
| 图渲染 | `@xyflow/react`（React Flow） | 局部流程图、影响范围图、copy_block 边界预览 |
| API 状态 | TanStack Query | 请求缓存、重试、失效、后台刷新 |
| 本地 UI 状态 | Zustand | 当前选中节点、面板展开、过滤器、临时草稿 |
| 路由 | React Router | 工作台、项目、版本、trace 详情等前端路由 |
| Diff/JSON 查看 | Monaco Editor | 只读 JSON、结构化补丁、diff 详情和开发者调试 |
| 图表 | Apache ECharts | 延迟、成本、token、失败率等观测图 |
| 表单校验 | Zod | 前端请求参数和反馈表单校验 |
| 测试 | Vitest + Testing Library + Playwright | 单元、组件和端到端验收 |
| 样式 | CSS Modules + Ant Design token | 页面级布局和品牌配色，不引入 Tailwind |

前端源码目录固定为：

```text
frontend/
  package.json
  vite.config.ts
  src/
    api/                  API client、类型、SSE client
    app/                  路由、Provider、全局错误边界
    components/           通用组件
    features/
      session/            会话、对话、需求澄清、模板确认
      planning/           修改计划、风险确认、补丁预览
      graph/              局部流程图、节点详情、影响范围
      versions/           版本历史、diff、回滚
      validation/         校验报告、导出检查
      observability/      trace、指标、成本、反馈
    styles/               token、布局、全局样式
    test/                 测试工具
```

构建产物固定输出到：

```text
app/static/workbench/
```

旧原型工作台先移动到或保留为：

```text
app/static/legacy/
```

FastAPI 根路径最终托管 `app/static/workbench/index.html`。如果需要保留旧入口，使用 `/legacy`，不得让两个工作台同时作为默认入口。

### 3.2 后端与事件流

| 分类 | 固定选择 | 用途 |
| --- | --- | --- |
| API | FastAPI | 继续作为唯一后端入口 |
| 工作流 | LangGraph `stream/astream` + `interrupt` + checkpointer | 事件流、确认点、恢复执行 |
| 默认事件流 | SSE，`GET /api/sessions/{thread_id}/events` | 单向推送工作流进度，满足主要生产场景 |
| 双向通道 | WebSocket，仅保留给开发者调试面板 | 后续需要实时调试输入时使用，不作为普通用户主通道 |
| 持久化 | PostgreSQL 优先，file 保持本地兼容 | 事件、trace、LLM 成本、反馈记录 |
| Trace | OpenTelemetry 语义 + 本地 trace 表 | 统一串联 API、Graph、LLM、补丁、校验、导出 |
| 指标 | Prometheus 格式 `/metrics` + ECharts 展示 | 延迟、错误率、token、成本、确认耗时 |
| 日志 | 结构化 JSON 日志 | 包含 `request_id/thread_id/project_id/version_id/trace_id` |

SSE 是阶段 7 的生产默认选择，原因是当前工作流主要是服务端向前端推送进度，用户输入仍通过 HTTP POST 完成。WebSocket 不先承担主链路，避免把确认、恢复、重试和断线重连复杂度提前放大。

### 3.3 可观测性数据表

在现有 `audit_events`、`patch_records`、`validation_reports` 基础上新增：

| 表 | 必要字段 | 用途 |
| --- | --- | --- |
| `workflow_events` | `event_id`、`trace_id`、`thread_id`、`project_id`、`version_id`、`event_type`、`step`、`status`、`payload`、`created_at` | SSE 回放、执行时间线 |
| `agent_traces` | `trace_id`、`thread_id`、`root_input`、`status`、`started_at`、`finished_at`、`error` | 一次用户请求的总链路 |
| `llm_call_records` | `trace_id`、`provider`、`model`、`prompt_name`、`attempt`、`latency_ms`、`input_tokens`、`output_tokens`、`estimated_cost`、`status`、`error` | LLM 成本和失败定位 |
| `user_feedback` | `trace_id`、`project_id`、`version_id`、`rating`、`category`、`comment`、`created_at` | 用户反馈和问题闭环 |

file 后端本地兼容时，用 `projects/events/` 和 `projects/traces/` 保存 JSONL；PostgreSQL 开启后以数据库为准。

## 4. 设计风格固定

### 4.1 视觉方向

工作台采用“美的蓝 + 工程控制台”的风格：专业、亲和、克制、信息密度高。界面第一屏就是可操作工作台，不做营销式落地页，不使用大面积装饰图、渐变光斑或无业务含义插画。

### 4.2 配色

正式上线应以美的品牌规范文件为准。阶段 7 开发先固定以下 UI token：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `mideaBlue` | `#0098D1` | 主按钮、当前状态、关键进度 |
| `mideaBlueDark` | `#006A94` | 顶栏、选中态、深色文字链接 |
| `mideaBlueSoft` | `#E7F6FB` | 浅背景、选中行、信息提示 |
| `ink` | `#172026` | 主文本 |
| `muted` | `#66737C` | 辅助文本 |
| `line` | `#D8E0E4` | 分割线 |
| `surface` | `#FFFFFF` | 面板 |
| `canvas` | `#F4F7F8` | 页面背景 |
| `success` | `#20704A` | 校验通过、可导出 |
| `warning` | `#A55C00` | 中风险、待确认 |
| `danger` | `#A53232` | error、阻塞导出 |
| `focus` | `#C97A34` | 键盘焦点和重要提醒 |

主色只用于关键路径，页面不能变成单一蓝色界面。风险、校验和成本信息必须用明确语义色区分。

### 4.3 布局

桌面端固定为四区工作台：

```text
顶部：项目名、当前版本、校验状态、事件流状态、导出按钮
左侧：项目类型、对话、结构化需求、待确认问题
中间：模板候选、修改计划、dry-run diff、风险确认
右侧：局部流程图、节点详情、校验问题
底部抽屉：版本历史、审计记录、trace、成本、反馈
```

移动端不追求完整工程编辑能力，只保证查看状态、回答澄清问题、确认模板/风险、查看校验结论和导出。局部流程图在移动端改为列表化影响范围。

### 4.4 交互原则

1. 普通用户入口只展示自然语言输入、模板确认、计划确认和导出检查。
2. 手写补丁 JSON 只放在“开发者调试”抽屉中，默认关闭，且必须标记为高级入口。
3. 所有高风险操作展示影响节点、风险原因、可回滚版本和校验摘要后才能确认。
4. 校验问题可点击定位到图中的节点或 diff 中的字段。
5. 版本回滚必须二次确认，并展示目标版本校验状态。
6. 页面按钮使用图标加短文本；不在页面上写冗长教学说明。
7. 卡片只用于模板候选、版本项、校验问题等重复实体；页面分区使用面板和分割线，不做卡片套卡片。

## 5. 完成顺序固定

### 7.1 API 契约和事件模型冻结

先做后端契约，不先写页面。

交付物：

1. 新增统一前端类型文档：`文档/阶段7前后端契约.md`。
2. 固定公开状态字段：`thread_id`、`status`、`next_action`、`project_id`、`version_id`、`validation_summary`、`risk_assessment`。
3. 新增 SSE 事件结构：

```json
{
  "event_id": "evt_...",
  "trace_id": "trace_...",
  "thread_id": "thread_...",
  "project_id": "project_...",
  "version_id": "v_...",
  "event_type": "workflow.step.started",
  "step": "plan_change",
  "status": "running",
  "message": "正在生成结构化修改计划",
  "payload": {},
  "created_at": "2026-04-29T10:00:00+08:00"
}
```

4. 新增接口：

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/sessions/{thread_id}/events` | GET | SSE 事件流，支持 `Last-Event-ID` |
| `/api/projects/{project_id}/versions/{version_id}/flow` | GET | 返回预算受控的局部 React Flow 节点和边 |
| `/api/traces/{trace_id}` | GET | 查询一次请求链路 |
| `/api/projects/{project_id}/traces` | GET | 项目 trace 列表 |
| `/api/feedback` | POST | 提交用户反馈 |
| `/metrics` | GET | Prometheus 指标 |

验收：

1. 断开 SSE 后可按 `Last-Event-ID` 续传未消费事件。
2. 所有事件都有 `trace_id` 和 `thread_id`。
3. 局部图接口默认不返回完整工程 JSON。

### 7.2 React/TypeScript 工作台脚手架

交付物：

1. 新增 `frontend/`。
2. 接入 Vite、React、TypeScript、Ant Design、TanStack Query、Zustand、React Router。
3. 建立 Design Token 和基础布局。
4. 建立统一 API Client，所有错误统一转成前端可显示结构。
5. FastAPI 默认托管 Vite 构建产物。

验收：

1. `npm run build` 通过。
2. `npm run test` 通过。
3. 根路径打开的是 React 工作台。
4. 旧静态工作台不再作为默认入口。

### 7.3 核心工程师工作流

交付物：

1. 项目类型按钮：机房群控程序、AHU 程序。
2. 会话创建、发送消息、澄清问题、确认需求清单。
3. 模板候选：匹配项、缺失项、预计改造成本、风险点。
4. 修改计划：LLM planner 尝试记录、结构化补丁摘要、dry-run 结果。
5. 高风险确认：风险原因、影响节点、可回滚版本、确认/取消。
6. 导出检查：校验通过才启用导出。

验收：

1. 从空会话到创建工程版本，全流程不需要手写 JSON。
2. 中高风险计划确认前不创建新版本。
3. 取消确认后当前版本不变化。

### 7.4 局部流程图和 diff

交付物：

1. 使用 `@xyflow/react` 渲染局部流程图。
2. 节点类型按工程角色区分：输入、输出、通讯、比较、PID、逻辑、保护、备注、未知。
3. 边方向固定按 `input_sources` 语义展示：上游源节点指向当前节点输入端。
4. diff 面板支持 added、removed、modified 三类。
5. diff 点击节点后，右侧图定位并高亮影响节点。
6. copy_block 预览显示入口端口、出口端口、内部连线和外部接线草案，不自动应用草案。

验收：

1. `/api/projects/{project_id}/diff` 的影响节点能在图中定位。
2. 大型工程只加载局部上下文，前端不卡死。
3. copy_block 默认不自动接外部线。

### 7.5 版本历史和回滚

交付物：

1. 版本时间线：版本号、父版本、创建时间、补丁摘要、校验状态、导出状态。
2. 版本对比：默认父子版本 diff，也支持任意两个版本对比。
3. 回滚确认：展示目标版本校验状态、当前版本、回滚后版本指针变化。
4. 回滚后刷新会话状态、版本列表、diff 和校验报告。

验收：

1. 回滚不删除历史版本。
2. 回滚到校验失败版本会被后端拒绝，前端显示明确原因。
3. 导出内容跟当前版本指针一致。

### 7.6 SSE 事件流和状态反馈

交付物：

1. 顶栏显示事件流连接状态：连接中、已连接、重连中、断开。
2. 工作流步骤条：需求分析、模板检索、模板确认、规划、dry-run、风险确认、提交版本、校验、导出。
3. 每个步骤显示耗时、状态和错误摘要。
4. SSE client 支持断线重连、`Last-Event-ID` 和重复事件去重。
5. LangGraph `updates`、interrupt、LLM 调用、补丁执行、校验和导出都写入 `workflow_events`。

验收：

1. 用户能看到长耗时任务正在做什么。
2. 刷新页面后能恢复最近事件。
3. 同一事件不会重复渲染。

### 7.7 Trace、指标、成本和用户反馈

交付物：

1. Trace 详情页：用户输入、Graph 节点、LLM 调用、补丁、diff、校验、确认、导出串成时间线。
2. 指标面板：请求量、错误率、P95 延迟、LLM 调用次数、token、估算成本、planner 重试次数、确认取消率。
3. 成本面板：按项目、供应商、模型、prompt、日期聚合。
4. 用户反馈：每次导出、失败、取消高风险操作后可提交评分、问题类型和备注。
5. 开发者调试抽屉：显示 `request_id/thread_id/project_id/version_id/trace_id/patch_record_id/validation_report_id`。

验收：

1. 开发者拿到一个 `trace_id` 能定位完整链路。
2. LLM 调用失败能看到供应商、模型、attempt、错误原因和耗时。
3. 每次导出可追溯到用户输入、计划、补丁、diff、校验和导出事件。

### 7.8 前端测试和验收样例

交付物：

1. Vitest 覆盖 API client、状态 reducer、事件去重、风险确认状态。
2. Testing Library 覆盖模板确认、补丁确认、校验报告、版本回滚组件。
3. Playwright 覆盖两条端到端路径：
   - AHU：选择模板、提出低风险修改、校验、导出。
   - 机房群控：中高风险补丁 dry-run、确认、版本 diff、回滚。
4. 视觉回归截图：桌面端 1440px、移动端 390px。

验收：

```powershell
conda activate midea
python scripts\build_indexes.py
pytest -q
cd frontend
npm run lint
npm run test
npm run build
npm run e2e
```

只改文档时可不运行上述命令；阶段 7 实现合并前必须运行。

## 6. 最终交付物形态

### 6.1 工程师视角

工程师打开工作台后，应能完成：

1. 明确选择“机房群控程序”或“AHU 程序”。
2. 按系统问题补充设备数量、控制目标、通讯、IO 和保护要求。
3. 看懂模板为什么被推荐，以及还缺什么。
4. 用自然语言提出局部改造。
5. 在应用前看到计划、风险、局部图、diff 和校验结果。
6. 对中高风险操作做明确确认或取消。
7. 通过版本历史对比和回滚。
8. 在导出前看到阻塞问题和修复建议。
9. 导出校验通过的 JSON。

### 6.2 开发者视角

开发者拿到问题后，应能用以下信息定位：

1. `trace_id`：进入 trace 详情页。
2. `thread_id`：恢复 LangGraph 会话和 checkpoint。
3. `project_id/version_id`：查看版本、diff 和校验报告。
4. `patch_record_id`：查看结构化补丁和 dry-run 结果。
5. `validation_report_id`：查看阻塞导出的具体问题。
6. `llm_call_records`：查看 prompt 名称、模型、attempt、token、成本和错误。
7. `workflow_events`：回放用户看到的事件流。

开发者调试入口必须在 UI 上可见但不干扰工程师主流程，默认折叠。

### 6.3 用户友好性底线

1. 用户不需要知道 patch op 名称也能完成常规修改。
2. 每个按钮的结果必须可预期：确认会创建版本，取消不会创建版本，回滚只切换当前指针。
3. 错误信息必须用业务语言解释，例如“目标版本校验未通过，拒绝回滚”，而不是只显示堆栈。
4. 任何导出失败都必须展示阻塞原因和校验报告入口。
5. 高风险确认必须说明影响范围和回滚路径。

## 7. 风险和边界

| 风险 | 应对 |
| --- | --- |
| React 工作台一次性做太大 | 严格按 7.1 到 7.8 顺序推进，每步可独立验收 |
| 局部图加载过大 | 后端局部图接口必须有 `max_nodes/max_edges/max_chars` 限制 |
| SSE 事件丢失 | 事件先落库再推送，支持 `Last-Event-ID` 续传 |
| 观测数据泄露敏感信息 | prompt、工程片段和 JSON 原文默认不进入指标，只用引用和摘要 |
| 手写 JSON 入口误用 | 默认隐藏到开发者抽屉，普通流程不依赖该入口 |
| 品牌色不准确 | 当前 token 作为开发基线，正式上线前以美的品牌规范复核 |
